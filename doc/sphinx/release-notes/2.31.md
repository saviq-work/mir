# Mir 2.31

(release-2.31.0)=

15 October 2026

## Requirements and compatibility

Building Mir now requires libxml++ 5.0; the older libxml++ 2.6 fallback has been removed. The
build also requires libwayland 1.24 or newer for the MirAL splash animation.

## What's new in [Mir 2.31.0](https://github.com/canonical/mir/releases/v2.31.0)

### Compositor-controlled output configuration

Compositor authors can use MirAL's {cpp:class}`miral::OutputConfiguration` strategy to customize
output settings before Mir applies them and to observe the configuration after it is applied.
Strategies can also be replaced at runtime ([#5224](https://github.com/canonical/mir/pull/5224)).
Mir also calls an existing `DisplayConfigurationPolicy`'s `confirm()` after a configuration
change ([#5259](https://github.com/canonical/mir/pull/5259)).

### Freely positioned magnifier

The built-in magnifier can now stay in a fixed position instead of following the cursor. Users can
move and resize it, and change its magnification, using on-screen controls with a pointer or one
touch contact. Compositor authors can select this behavior through the MirAL API or live
configuration ([#5135](https://github.com/canonical/mir/pull/5135), [#5207](https://github.com/canonical/mir/pull/5207)).

See {doc}`/explanation/accessibility-methods` for details.

## Minor features

### Workshop SDK and platform development

The new Mir SDK for Workshop provides Mir's installed headers, libraries, tools, and platform
plugins under `/opt/mir`, so a consumer SDK can build a compositor against MirAL
([#5294](https://github.com/canonical/mir/pull/5294)).

Display sinks can now describe how renderables map to direct and composited layers, and report
presentation results to the compositor. This gives display-platform implementations an explicit
way to plan hardware composition ([#5290](https://github.com/canonical/mir/pull/5290)).

Platform APIs now separate display and rendering providers, with a new blitter provider and
framebuffer-pool and software EGL-context support ([#5213](https://github.com/canonical/mir/pull/5213),
[#5293](https://github.com/canonical/mir/pull/5293)).

`DisplayInfo` now includes an optional physical address
([#5291](https://github.com/canonical/mir/pull/5291)).

### Wayland protocol definitions

Mir now includes the testing-phase `ext_foreign_buffer_v1` protocol definition. It describes
compositor-managed buffers backed by image-capture sources, but this change adds the protocol
definition only; it does not add runtime support in Mir's Wayland server
([#5203](https://github.com/canonical/mir/pull/5203)).

### Input, display, and shell fixes

- Libinput's circular-scrolling mode can now be configured ([#5246](https://github.com/canonical/mir/pull/5246)).
- Input events are scaled correctly when display transformations are active, and input-trigger
  modifier checks no longer reject valid key bindings ([#5292](https://github.com/canonical/mir/pull/5292),
  [#5249](https://github.com/canonical/mir/pull/5249)).
- Fullscreen composition bypass is disabled when output filters or transformations require composition ([#5310](https://github.com/canonical/mir/pull/5310)).
- Mir now enforces the `xdg-decoration` v1 buffer/configure rules, returning `unconfigured_buffer`
  when a buffer is attached before the first configure
  ([#5313](https://github.com/canonical/mir/pull/5313)).
- MirAL splash screens now fade in smoothly instead of pausing between frames ([#5297](https://github.com/canonical/mir/pull/5297)).
